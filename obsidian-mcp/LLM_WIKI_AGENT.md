# LLM Wiki 에이전트 지침 (schema)

이 파일이 카파시(Andrej Karpathy) 방식의 "schema"입니다 — 이 Vault의 위키가 어떻게
구조화돼 있는지 LLM에게 알려주는 문서입니다. Obsidian Vault 루트에 두면 Claude
Desktop(Obsidian MCP 연동)이 이 지침에 따라 Vault를 관리합니다. 자세한 배경은
[docs/06-카파시-llm-wiki-graphify.md](../docs/06-카파시-llm-wiki-graphify.md) 참고.

## 폴더 구조

- `raw/` — 소스 원문 그대로 보관(글, 논문, 대화 내용, 크롬 확장으로 저장한 노트 등). 수정하지 않음.
- `wiki/` — AI가 정리한 위키 페이지. 하나의 개념 = 하나의 파일.

## 세 가지 동작

### 1. ingest (반영)
`raw/`에 새 파일이 추가되면:
1. 핵심 개념을 뽑아 `wiki/개념명.md`로 정리한다 (없으면 새로 생성, 있으면 갱신).
2. 관련된 다른 위키 페이지가 있으면 `[[개념명]]` 형식으로 서로 연결한다.
3. 이미 있는 페이지와 내용이 겹치면 합치고, 원문 링크(어느 `raw/` 파일에서 왔는지)를 남긴다.

### 2. query (질문)
사용자가 질문하면:
1. 먼저 `wiki/`의 관련 페이지를 찾아 답한다 — `raw/` 원문을 매번 다시 읽지 않는다.
2. `wiki/`에 답이 없으면 `raw/`를 검색하고, 답을 찾으면 새 위키 페이지로 `wiki/`에 저장한다.

### 3. lint (정합성 점검)
가끔(사용자가 요청하거나 새 위키 페이지가 여러 개 쌓였을 때):
1. 서로 모순되는 내용이 있는 페이지를 찾아 알린다.
2. 링크가 끊긴 `[[개념명]]`이 있으면 알린다.
3. 오래돼 더는 맞지 않는 내용이 있으면 갱신을 제안한다 (자동 삭제는 하지 않고 확인을 받는다).

## 원칙

- 위키 페이지는 위키백과 스타일로 — 하나의 개념을 명확하게, 장문 요약이 아니라 참조 가능한 형태로.
- 확실하지 않은 내용은 위키 페이지에 그대로 사실처럼 쓰지 않는다 — 원문을 다시 확인하거나
  사용자에게 확인을 구한다.
- `raw/` 원문은 절대 수정하지 않는다 — 편집은 항상 `wiki/`에서만.
